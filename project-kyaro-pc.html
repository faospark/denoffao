Project Kyaro: Suikoden I & II HD Remaster Suite.

The Project Kyaro Suite is a modern BepInEx 6 IL2CPP runtime plugin designed specifically for the Suikoden I & II HD Remaster on PC. Built to work seamlessly with SuikodenFix, it delivers comprehensive DDS texture replacements, dynamic character portraits framework, sprite smoothing, UI customization, performance optimizations, and quality-of-life enhancements—all fully configurable without Special K.

- [Command Rune Unbalance Penalty Removal] Added configurable removal of the Unbalance status effect
  penalty and dizzy stars animation after using high-powered physical ability runes in Suikoden 2 (Titan,
  Falcon, Viper, Shrike, Swallow, Trick, Fire Breath, Mayfly, Lion, Unicorn, Pixie, Blue Drop).

- [Battle Party Max HP Display] Added ShowBattleMaxHP toggle (on by default) under [02 User Interface]
  to display both current and maximum HP (e.g. 587/587 instead of just 587) in the battle party
  window for Suikoden 1 & 2. Features dynamic text mesh auto-sizing to eliminate clipping or overflow.

- [Disable UI Tips Overlay] Added DisableUITips toggle under [02 User Interface] to hide the
  persistent button/control prompts overlay (UITips) across battles, menus, and field screens in
  both Suikoden 1 and Suikoden 2, while preserving tips on the main launcher scene.

- [Summon & Battle Magic Crash Fix] Fixed severe frame drops, memory spikes, and crashes when
  casting high-tier summon spells (e.g. Pale Gate Rune) in Suikoden 2 by removing intrusive
  interceptions and allowing the native effect engine to handle animations cleanly.

- [Texture Pipeline Caching & Memory Fix] Fixed a memory leak where temporary DDS textures accumulated
  in memory during gameplay, and added an in-memory byte cache (rawFileBytesCache) to accelerate
  texture swaps and eliminate duplicate disk I/O.

- [Battle Window Diagnostics] Added LogBattleUnitWindow diagnostic toggle under [zz - Diagnostics]
  to inspect and log battle party UI text elements, hierarchies, and slot structures once per battle.

Installation [Very Important!!!]

Follow these 4 simple steps to ensure a flawless setup.

Easy 4-Step Process

Step 1: Remove Old Files (If you were using an old Special K version)

Delete the following files and folders from your game directory:

  • BepInEx/plugins/PKextended.dll
  • BepInEx/config/faospark.pkextended.cfg
  • dxgi.dll or d3d11.dll (whichever Special K injector file you used)
  • Entire SK_Res/ folder (no longer needed—PKCore handles textures natively and differently)

Step 2: Ensure You Have BepInEx Installed

(If you already have SuikodenFix installed, you may skip this step.)
Download BepInEx 6.0.0-pre.2 IL2CPP build from GitHub Releases and extract the contents to the game directory (where Suikoden I and II HD Remaster.exe is located). Replace the files if asked.

Step 3: Install Project Kyaro Suite

Download Project Kyaro Suite from Nexus Mods (#6).
Extract the package directly to your game directory. Overwrite if asked.

Step 4: Launch Game

Run Suikoden I and II HD Remaster.exe. PKCore will automatically:

  • Auto-generate new configuration file: BepInEx/config/faospark.pkcore.cfg
  • Load with all default settings enabled

You are done! You can explore and customize other options in BepInEx/config/faospark.pkcore.cfg.

Known Bugs & Incompatibilities

Transparent documentation of known quirks and their simple workarounds.

Known Quirks
  • Window Sets Selection Marker: A recently reported quirk when using Window Sets. The Yellow Select Marker can occasionally bug out as the game starts using random textures. The cause is still being investigated as it can also occur in the vanilla game without using the mod. The easy fix is simply to save and reboot the game.
  • Neclord's Castle Zombie (Suikoden 1): A visual artifact that naturally resolves itself as you progress to the Neclord Castle mission. It occurs because the sprites for the zombie summoned by Neclord in town and the castle zombie share the same memory location. The town zombie is upscaled by default, causing a visual bleed because the zombie in the castle basement was originally hidden from view in vanilla (without the mod, you could talk to an invisible field entity).
  • Third Summon Sprite: Simply does not want to be replaced by the Unity engine hooks, so it has been left as is.
  • Whack-A-Mole Sprites: Another sprite group that resisted scaling algorithms, so the default size asset was replaced cleanly instead.

Important Notice & Disclosures

Philosophical background on pixel art algorithms, image placeholders, and preservation.

Use of Pixel-Art Scaling Algorithms

This mod is created out of deep respect for the original pixel art and the artists behind Suikoden. Project Kyaro does not aim to replace, diminish, or disrespect pixel art. It simply offers an optional visual alternative for players who feel the contrast between pixel sprites and smoothed backgrounds can be visually inconsistent.

This technology has existed since the 1980s and is prominently featured in many modern-day emulators. This mod particularly uses Rebout and Rebout Blend by Lyonheart.

Please do not use this space to debate pixel art vs. upscaling or argue that the mod "should not exist." We love pixel art too. If you prefer the original look, that is perfectly fine — this mod is for players who want a different presentation style, and in recent versions you can turn it off anytime in config.

Disclosure of use of Machine-Learned Tools to Manipulate Images (Portraits / Placeholders)

Portraits in this mod are based on existing game artwork from other releases and were adjusted using modern image-manipulation tools. The goal is not to replace or reinterpret the original artists' work — it's to keep the portraits as close to the game's artwork as possible so the visual experience remains consistent. To put it simply: make it look presentable.

  • I do not claim to be an artist or drew these placeholders, nor do I say these images are art. They are placeholders to keep the UI uniform.
  • These edits act as stylistic bridges, not replacements, because in the first place they never existed in the original game, on their rerelease, or in the remasters.
  • The portrait feature / framework is 100% optional and can be toggled off or replaced with your own custom assets. You are under no obligation to use the portraits feature.

A Personal Anecdote

I’m sharing this for context and educational purposes, so people can better understand what goes into this project—or at least one part of it. I get the criticism, but some of you go way overboard.

One benefit of publishing on NexusMods is access to reasonably accurate audience data. When the portrait feature was first released, that version of the mod was downloaded only 107 times. Compared with the estimated 55,651 Steam owners of Suikoden I & II HD Remaster (lowest estimate), that’s roughly 0.2% of the player base. Yet certain people reacted as if this mod were causing massive harm to the entire Suikoden community.

Now, about the portraits component—let’s put things into perspective. I asked someone at a major U.S. studio about production costs. Their blunt advice: “Go offshore if you want it affordable.” Even with reduced scope (headshots instead of half-body portraits), the math is significant: 100 character headshots at $20 each is about $2,000 USD. And that assumes ideal conditions: funding available, multiple artists willing to work under mod constraints, and fast turnaround. In practice, those assumptions are hard to meet for an indie team… let alone a single enthusiast. That kind of money is already like two years of college in my country. Yet some individuals adamantly demanded I “hire artists,” as if I—a random office worker in a developing nation—have thousands to spend out of pocket for images Konami itself didn’t bother to invest in. One person even demanded I release the portraits feature without placeholders. Babes, I don’t look at a billboard and imagine the advertisement. I don’t buy ramen noodles and imagine the contents.

So ask yourself: is it realistic to expect hobbyists to meet those demands? Especially for content Konami itself never funded. These portraits weren’t part of the original release, the PSP rerelease, the older Chinese PC version, or the HD Remaster.

Let’s keep perspective. Imagine being upset over an optional feature you can disable. Imagine treating a mod that serves 0.2% of Steam owners, not 2%, as if it’s some massive problem. Imagine demanding a fan project absorb labor, time, and resource costs the original company never took on—effectively asking it to outspend Konami just to satisfy people who may not even play the game. Imagine being angry over “stolen portrait jobs” that Konami never commissioned in the first place. There’s a real sense of disproportionality and misplaced anger here. It’s a free mod. Nobody is obligated to use it. And portraits are just one component out of 40+ others. Like, calm down.
